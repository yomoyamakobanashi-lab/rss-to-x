# まこの映画小話 — editorial & publishing contract

## Editorial bank
`data/mako_film_stories.json` is an append-only JSON array. Initial release requires at least 20 source-checked stories for EACH weekday (140 total). Do not mark a draft source_checked merely because it has URLs. Read the source text and map each material factual claim to evidence. For contested history, psychology, rumours, conspiracy or alleged real incidents, cross-check independent credible sources; distinguish fiction, folklore, documented fact and interpretation. No personal-account reviews, invented quotes, citations or diagnoses. Prefer scholarly publications, official film/studio archives, museums, universities and trusted trade media; avoid copying prose. No sensitive personal claims or sensationalism. Keep story IDs and topic_key values globally unique; never recycle a previously used story or same substantive angle. The first post contains #まこの映画小話 and searchable film/topic terms, no links. 3–6 authored segments, each conservative weighted length <=280 including auto-numbering and #リルパル. Source replies and final verified podcast CTA are generated automatically; do not include them in posts. Optional episode_guid must be matched to the exact catalogue and be genuinely relevant. Otherwise show URL is used. No LISTEN links in public copy.

Weekday codes: 0 Monday 映画怪異録; 1 Tuesday 銀幕陰謀論; 2 Wednesday シネフィルの処方箋; 3 Thursday 映画心理学講義; 4 Friday 銀幕人文学; 5 Saturday 映画の舞台裏; 6 Sunday 映画トリビア研究所. For each source store name, https URL, supports (what claim it verifies); checked_on ISO date, review_status=source_checked. Confirm references actually load, and record enough detail for later editorial review.

## Poster-first hook (added 2026-11-27)
Prefer the original or authorized theatrical poster for the actual film/version/year, attached natively to the first post only. Never scrape or automatically reupload a random search result, personal account, TMDB/IMDb poster, or press image whose reuse terms are unclear. Public availability, attribution, or an official studio account alone do not confer reuse permission. Confirm original source, authorship, rights in Japan and relevant territories, and permission for promotional social media; do not rely on a PD label alone if provenance or applicable territory is uncertain. For modern titles prioritize distributor press kits with explicit applicable terms; if permission is not established, leave poster pending and publish text only, or design a rights-clear original typographic card in a separate future workflow. No generated counterfeit official posters.

Optional poster object: status=pending (not attachable; record candidate URLs and review_note) or rights_checked (required film_title, year, source_url, image_url, license, rights_evidence_url, rights_basis, credit, checked_on). Only explicit eligible license or documented rightsholder permission, approved direct HTTPS asset host, and valid image response qualify. Approved direct hosts currently upload.wikimedia.org; extend only after confirming a trusted official file host. Record creator/source/license in a reference reply before the final listening CTA. Keep images original unless a license explicitly permits modifications. Preflight failures fall back to text before reserving the posting slot; never resend a potentially accepted post. Initial release still requires 20 source-checked stories per weekday, not 140 posters of uncertain rights. Track poster clearance separately, prioritize clearing images for stories with actual film titles. Re-audit the first seven drafts' references against actual pages and correct or hold any unsupported claim before production. Confirm image-plus-thread payload in real CI using mocks and validate actual root/reply publication after release; no test publishing from draft PR.

## Unified publication
Only .github/workflows/mako-film-stories.yml may publish automatically after cutover. Independent legacy workflows are retired; transcript/ingest, RSS, and analytics workflows stay active. One story from 07:00 JST + one companion per JST date. New podcast announcement wins; if none is eligible, funny clip from 19:30 JST. Late new episode after the companion slot has been spent cannot be announced that day without breaking the hard cap; do not exceed cap. No automated note/trend/audiogram or survey posts. All publication uses existing Buffer thread API. Ledger is committed before sending to prevent duplicate uncertain submissions. Accepted ID and confirmed root URL are distinct; root confirmation does not prove every reply appeared. Never blindly retry an ambiguous mutation; inspect Buffer/X and reconcile manually if needed. Manual X posts and external tools outside GitHub are not controlled.

## Release procedure
Keep main untouched until the source-checked bank has >=20 per weekday, all tests pass on the PR head and old publishing workflows are audited. Set state_mako_publish.json start_jst to the next JST date before merge, run validation again, ensure no old publishing runs are in progress and merge atomically. Verify the final workflow run and actual X root/reply status as far as API permits. Do not claim a successful X publication solely from Buffer acceptance. Monitor for cutover problems. After release maintain at least 5 unused per weekday; if below 5 replenish to 20 unused, preserving used history. No blind resubmission or deletion of existing posts.
